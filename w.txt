PHASE 1 — FOUNDATION, HARDENING & KEYLESS CODING-AGENT MODELS
================================================================================
Goal: Fix scope-escape risks in research.go, add Claude Code / Codex as keyless
LLM backends, wire telemetry/plugin parity, and wrap high-priority CLI scanners.

[CLAUDE]
  1. Research Organ Security Hardening (internal/arsenal/research.go):
     - Wire checkURL(ctx, ...) and redirect-target scope validation into
       probeGET and probePOST so execute=true strictly obeys ROGUE_SCOPE,
       ROGUE_EXCLUDED, and ROGUE_ALLOWED_PORTS.
     - Gate execute=true through Policy.Approve when running in default mode.
     - Fix cerberus_privesc local checks: use `sudo -n -l` (non-interactive) and
       tolerate partial stdout from `find` when unreadable paths return err != 0.
  2. Engine Inspection Seam (internal/engine/):
     - Define optional Inspector interface + WarRoomSnapshot struct (tasks,
       kill-chain phase status, 8 operator states/risks, target inventory,
       findings, OPSEC signals, budget/metrics).
  3. Priority External CLI Wrappers (internal/arsenal/):
     - Wrap ffuf, gobuster, nikto, sqlmap, openssl, wget, and host using
       ProcessRunner (stripped env, explicit allowlisted flags, 2 MiB caps).

[CODEX]
  1. Keyless Coding-Agent Providers (internal/llm/ + internal/tui/setup.go):
     - Add `claude-code` (claude -p stream-json) and `codex` (codex exec JSON)
       implementing llm.Provider so ROGUE can run using local authenticated
       coding-agent sessions with no separate LLM API key.
     - Add Hermes / fallback chain wiring matching T3MP3ST's resilient calls.
     - Register providers in llm.Providers, update /provider TUI setup,
       --check-provider, and add GET /api/codex/status & POST /api/codex/probe
       in internal/api/.
  2. Telemetry & Plugin Hook Parity (cli.go, internal/api/, internal/mcp/):
     - Pass Metrics (telemetry.Collector) and Plugins (plugin.Registry) into
       --serve, --mcp, and TUI execution paths so lifecycle hooks and counters
       fire consistently across all modes, not just --assess.

PHASE 4 — TUI-ORIENTED WAR ROOM (ADDED LAST)
================================================================================
Goal: Build the War Room natively inside ROGUE's Bubble Tea v2 TUI on top of
the completed Phase 1-3 engine, Inspector seam, OPSEC presets, and benchmarks.

[CODEX]
  1. War Room Shell & Adaptive Layout (internal/tui/):
     - Add `/warroom` command and `ctrl+w` toggle (plus `esc` back to chat)
       without interrupting running turns; stay faithful to theme.go's dark
       wine-plum (#130911) foreground-only palette.
     - Wide terminals (width >= 120): Split layout — Left (58%) 7-stage Kill
       Chain stepper + live ops/transcript feed + input box; Right (42%)
       tabbed inspector pane.
     - Standard terminals (80-119 cols): Full-screen tabbed view with a 2-line
       persistent telemetry bar (mission ID/status, phase stepper, mode, OPSEC
       meter, token/USD budget).
  2. Six TUI War Room Panels (`1`-`6` tabs):
     - [1] Ops / Kill Chain: Phase stepper (`RECON -> WEAPONIZE -> DELIVER ->
       EXPLOIT -> INSTALL -> C2 -> ACTIONS`), streamed operator-tagged events,
       `enter` to inspect full tool JSON/output in a pager.
     - [2] Operators: 8-archetype roster (`Callsign | State | Done/Fail | Risk`
       bar) + `j/k` bottom Dossier Drawer (MITRE tactics, ToolCats, task).
     - [3] Targets: Collapsible tree (`Host -> Port/Proto -> Service/CPE ->
       Candidate CVEs -> Findings`), severity-colored.
     - [4] Vault: Findings table filterable by severity (`c/h/m/l/i`), `enter`
       for CVSS v3.1 vector & access path, `e` to export JSON/SARIF/HTML/MD/PDF.
     - [5] Arsenal: Live tool catalog (`nmap [ok] / sqlmap [missing]`), scope/lab
       badges, and inline quick-run modal.
     - [6] OPSEC & Bench: Preset switcher (`Silent`/`Covert`/`Loud`,
       `Balanced`/`Stealth`/`Breach`), IOC log, detection meter, and live
       Cybench/NYU/JuiceShop benchmark scoreboard.
  3. Interactive Approval Modal (TUI-Native Killer Feature):
     - When `mode == default` and a tool requires approval, show a centered
       approval card with exact tool, target, and arguments:
       `[y] allow once  [a] allow for mission  [n] deny`.

[CLAUDE]
  1. Engine <-> TUI Interactive Hooks & Final Verification:
     - Wire real-time interactive ApprovalController callback channel from
       Harness into the TUI event stream (and pause/resume control on `space`).
     - Run end-to-end verification across TUI War Room, CLI, `--serve`, `--mcp`,
       and benchmark suites.

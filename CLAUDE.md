## Post-Change Teaching Workflow

After completing any code changes (new features, bug fixes, refactors), automatically invoke the `teach` skill to debrief the user on what was changed. This is the default behavior unless the user explicitly says to skip it (e.g., "no teach", "skip the lesson", "don't quiz me").

The teach debrief should:
- Explain what changed and why
- Cover key decisions, tradeoffs, and dependencies
- Quiz the user to verify understanding
- Track mastery progress in `teach-progress.md`

This applies to implementation work, not to questions, explanations, or config-only changes.
